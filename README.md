# 座舱测试 Agent（dsh-cts-agent）

在 DeepSeek Harness 里开一个**独立的测试工作台页面**：左侧是项目资料，中间是 agent 工作区（工具调用可见），右侧是产物。agent 通过 `ctx.llm` 调用模型，所以整个 DSH 共用一套模型配置。

当前版本 **6.0.1**：产品事实 → 测试点 → 用例全链路可编辑、可审查、可导出；输入支持 docx / xlsx / md / html / csv / pdf / dbc，并接入 **Pixso 设计稿**（内置 vendor/pixso 解码器，旧编译结果可直接复用）。

6.x 在早期版本之上补齐了流水线门槛：需求合同逐条确认、测试大纲批准后才可生成下游；交付包可冻结/派生版本；导出 xlsx / html / json / md；评审按对象逐 ID 留回执并统计首审；另有活动记录、作者/评审角色、用例配图与 Pixso OAuth 授权。

## 用法

1. 安装后在左侧边栏点「测试 Agent」，进入的是**工作台**：最近项目卡片、生成配置状态和工作流说明；不会一进来就弹创建表单。
2. 一级导航只有「工作台 / 资产中心」；ECSM / 测试设计 / 交付属于项目内页面，不会在工作台出现。
3. 点项目卡片进入**项目首页**，先选模块（每个模块的产物、资料范围、测试设计相互独立）。
4. 进入新模块先到**「第一步：添加资产」**：可以上传新资产（自动打本模块标签），也可以从项目资产池挑选已有资产并打标签；加完再进入 ECSM。
5. 资料统一在「资产中心」查看/上传；设计稿解析、Skill 管理等高级能力可从资产中心的「资料工具」进入。构建证据或生成 ECSM 时会按资料自动识别生成配置。
6. 进入 ECSM 会显示“产品模型准备”向导：按资料/证据/上游/合同/冻结的当前状态给出唯一主按钮，不需要自己判断下一步。
5. 在输入框里问一句，例如「这个项目里有什么资料？」。

> 已有项目时顶栏始终有「+ 新建项目」；只读项目可以查看，不能改名/删除/改生成配置。

## 项目、模块与生成配置

- **新建项目**：顶栏「+ 新建项目」，只需项目名和首个模块名；创建后直接进入「资产中心」，上传资料并构建证据。
- **项目设置**：顶栏「项目设置」可改名、删除项目（一次确认、永久删除）、增删/改名模块。
- **生成配置**：项目设置 → 生成配置。不是账号/项目分类，而是给生成器的说明书：项目是纯文档还是带 DBC/设计稿、需求文件在哪、界面叫什么；会影响来源解析、信号校验和用例里的页面名。**正常流程不需要手动填**：上传资料后构建证据/生成 ECSM 会自动识别；项目设置里可用「从项目资料识别」或手动微调页面词表。
- 自动识别需要至少一份 PRD；没有 PRD 时无法生成配置。页面词表若项目里有同名 PRD 的完整项目会自动复用，否则先用通用「页面」，可在项目设置里微调。**识别过程不弹常驻提示**，构建证据成功时会提示“已按资料自动识别生成配置”。

## 配置

在 profile 的 `cordis.patch.yml` 里覆盖，不要改这个包里的文件：

```yaml
- id: cts-agent
  config:
    dataDir: /Users/you/Documents/CTS-testagent
    legacyRoot: false          # 与旧工作台数据完全隔离
    sourceRoots:
      - /Users/you/Documents/ChatGPT/crewai/data/projects   # 只读的旧工作台
    provider: deepseek-official
    model: deepseek-flash
```

`sourceRoots` 里的项目以只读方式列出，用来和旧系统对拍；`legacyRoot: false` 时不再自动挂载旧工作台。当前本机 desktop profile 已指向 `~/Documents/CTS-testagent`。

### Pixso MCP（设计稿取图）

两种接法，默认先试本地，配了令牌则走云端：

```yaml
    # 云端（推荐，无需装桌面端）
    pixsoToken: <Pixso 个人访问令牌>
    # 或显式指定地址（本地/私有化环境）
    pixsoMcpUrl: https://pixso.cn/mcp
```

| 模式 | 地址 | 需要的 | 能拿到 |
|---|---|---|---|
| 云端 Remote MCP | `https://pixso.cn/mcp` | 个人访问令牌（用户中心 → 个人访问令牌） | `get_export_image`（PNG/SVG/WebP）、`get_node_dsl`、`take_screenshot` |
| 本地 Local MCP | `http://127.0.0.1:3667/mcp` | Pixso 桌面端 + 打开文件 + 开启 Local MCP | `get_screenshot`、`get_node_dsl` |

云端 MCP 需要「全功能 / 研发席位」，账号没席位时所有工具都会返回 `-32008 Access denied`（连官方示例文件也一样）。这种时候改用本地：

```yaml
    pixsoMcpUrl: http://127.0.0.1:3667/mcp
```

本地不受席位限制，但要求 Pixso 桌面端开着、目标文件打开着。Windows / macOS 地址都是 `127.0.0.1:3667`，配置各机器独立。

**推荐用 OAuth**：资产页「Pixso MCP → 授权登录」，跳 Pixso 授权后自动把令牌存到 `<dataDir>/pixso-oauth.json`，不用手工粘令牌。

用令牌也可以：Pixso 工作台 → 右上头像 → 用户中心 → 个人访问令牌 → 生成（只显示一次），填到 `pixsoToken`。
注意：实测有的个人访问令牌会被 MCP 端点判为 `invalid_token`，那种情况请改用 OAuth。
调用需要**全功能或研发席位**，且对目标文件有查看权限。

## 数据

- 运行日志：`<dataDir>/runs/<projectId>/<runId>.jsonl`，页面刷新后从这里重放。
- 不写旧工作台的任何文件。

## 证据与交付

- 新项目首次构建证据时按文档标题切块，块的位置取块首标题（引用可定位到具体章节）；已有证据库保持原块粒度，重复构建时按原文摘要认领旧证据编号，避免下游事实引用漂移。需要重新切块时，在 `projects/<项目>/project.json` 的 `quality` 里写 `"evidence_chunk": "heading"`（或 `"size"` 强制块内聚合）后再重建证据；重建会重排证据编号，需同步重新生成事实/合同。
- 交付包导出 `xlsx / html / json / md` 与图片目录；状态机 `states.json` 带内容摘要 `digest`，可与其他工件统一做版本对账。
